# Quick Task 260809-q0t: 滑动续期（sliding token refresh）

## 背景与根因

**期望行为（用户锁定，不再讨论）：**
1. **Refresh token 存 DB**（不透明随机串，存 SHA-256 哈希，可吊销，支持真正的退出登录）。不是无状态的长效 JWT。
2. **Access token 缩短到几小时**让刷新真正被用到；**refresh token 长效 + 滑动窗口**——每次刷新轮换：签发新的 access token + 新的 refresh token（新的过期时间），旧 refresh token 作废。活跃用户永不被登出；超过 refresh TTL 的静默用户会被登出（可接受）。
3. **前端 401 自动刷新并重试原请求一次**。只有刷新本身失败才跳登录页。

**根因（已核实）：**
- 后端当前是无状态 JWT。`JwtUtil.generateToken` 设 exp = now + `jwt.expiration`（application.yml 86400000ms = 24h）。无 refresh 端点、无 token 存储、无 `/refresh` 路由。
- `src/axios/client.ts` 响应拦截器对 401/403 直接 `localStorage.removeItem(...)` + `window.location.href = '/login'`——即「使用中被硬踢到登录页」的元凶。
- `AuthController` 有 `/logout` 但只返回 success 不吊销任何东西；`/login` `/register` 只签发一个 access token。
- DB 是 MySQL，schema 手工维护在 `backend/sql/schema.sql`，**没有迁移工具**。新表必须加进 schema.sql **并且手动应用到运行中的 MySQL**（localhost:3306，root/123456，库 `tauri_mark`）——不做这个后端一跑登录/刷新就会 500/404。这一步必须显式说明。
- `/api/auth/**` 在 `SecurityConfig` 已 permitAll，所以 `/api/auth/refresh`、`/api/auth/logout` 天然公开，无需改 SecurityConfig。

**保持既有行为（约束）：**
- 保留自动登录（token 持久化在 localStorage）、启动时 `validateToken()` 校验（`main.ts` 先校验再挂载 router）——现在校验会经由拦截器自动刷新兜底。
- 不删除现有端点，只扩展（login/register 也发 refresh token；logout 变吊销；change-password 吊销该用户全部 refresh token）。
- 401 只在「受保护接口且刷新失败」时才跳登录页；`/api/auth/login|register|refresh|logout` 自身的 401 不触发刷新（避免死循环）。

## 任务 01：DB schema —— 新增 refresh_tokens 表 + 手动迁移到运行中的 MySQL

**文件：** `backend/sql/schema.sql`

**动作：**
- 在 `backend/sql/schema.sql` 末尾追加建表语句（`CREATE TABLE IF NOT EXISTS`，幂等，可整库重放）：
  ```sql
  -- 刷新令牌表（滑动续期）
  CREATE TABLE IF NOT EXISTS refresh_tokens (
      id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '自增ID',
      user_id BIGINT NOT NULL COMMENT '所属用户',
      token_hash VARCHAR(64) NOT NULL COMMENT 'refresh token 的 SHA-256 哈希（十六进制）',
      expires_at DATETIME NOT NULL COMMENT '过期时间',
      revoked TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否已吊销/已旋转作废',
      created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
      updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
      UNIQUE KEY uk_token_hash (token_hash),
      INDEX idx_user_id (user_id),
      INDEX idx_expires_at (expires_at)
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='刷新令牌表';
  ```

## 任务 02：后端 —— refresh token 机制（TTL、实体/Mapper/Service、login/register/refresh/logout/change-password）

**文件：**
- `backend/src/main/resources/application.yml`
- `backend/src/main/java/com/taurimark/entity/RefreshToken.java`（新建）
- `backend/src/main/java/com/taurimark/mapper/RefreshTokenMapper.java`（新建）
- `backend/src/main/java/com/taurimark/service/RefreshTokenService.java`（新建）
- `backend/src/main/java/com/taurimark/dto/AuthResponse.java`
- `backend/src/main/java/com/taurimark/dto/RefreshRequest.java`（新建）
- `backend/src/main/java/com/taurimark/service/AuthService.java`
- `backend/src/main/java/com/taurimark/controller/AuthController.java`

**动作：**

1. `application.yml`：把 access token 缩到 2 小时，新增 refresh TTL 配置：
   ```yaml
   jwt:
     secret: tauri-mark-secret-key-2024-very-long-and-secure
     expiration: 7200000          # 2 hours in milliseconds（access token，缩短以便真正滑动）
     refresh-expiration: 604800000  # 7 days in milliseconds（refresh token，滑动窗口）
   ```

2. `entity/RefreshToken.java`（新建，仿 `User.java` 手写 getter/setter，不用 Lombok）：字段 `id, userId, tokenHash, expiresAt(LocalDateTime), revoked(Boolean), createdAt, updatedAt`。

3. `mapper/RefreshTokenMapper.java`（新建，仿 `UserMapper` 注解式）：
   - `insert(RefreshToken)`：`INSERT INTO refresh_tokens(user_id, token_hash, expires_at) VALUES(#{userId}, #{tokenHash}, #{expiresAt})`，`@Options(useGeneratedKeys=true, keyProperty="id")`
   - `findByTokenHash(@Param("tokenHash") String)`：`SELECT * FROM refresh_tokens WHERE token_hash = #{tokenHash}`
   - `revokeById(@Param("id") Long)`：`UPDATE refresh_tokens SET revoked = 1, updated_at = NOW() WHERE id = #{id} AND revoked = 0`
   - `revokeAllByUserId(@Param("userId") Long)`：`UPDATE refresh_tokens SET revoked = 1, updated_at = NOW() WHERE user_id = #{userId} AND revoked = 0`

4. `service/RefreshTokenService.java`（新建 `@Component`）：封装哈希与存储，供 AuthService 调用：
   - 常量 `TOKEN_BYTES = 32`（256-bit 随机）；`@Value("${jwt.refresh-expiration}") Long refreshExpiration`
   - `create(Long userId)`：`SecureRandom` 生成 32 字节随机串 → hex 作为明文 token 返回；同时把 `SHA-256(明文)` 哈希 + `userId` + `expiresAt = now + refreshExpiration` 插入 DB。
   - `findByRawToken(String raw)`：返回 `findByTokenHash(sha256(raw))`（哈希只在此处算，其余地方不重复）。
   - `revoke(String raw)`：空值直接返回；按 `sha256(raw)` 调 `revokeByTokenHash`（Mapper 可加一个 `revokeByTokenHash`，或先 `findByTokenHash` 再 `revokeById`，任选其一保持一致）。
   - `revokeAllForUser(Long userId)`：`revokeAllByUserId`。
   - `sha256(String)`：`MessageDigest.getInstance("SHA-256")` + `HexFormat.of().formatHex(bytes)`（JDK17）。

5. `dto/AuthResponse.java`：新增字段 `refreshToken`（+ getter/setter），新增 4 参构造 `(token, refreshToken, username, userId)`；保留原 3 参构造（`/current` 仍用 3 参，refreshToken 传 null）。注意 `application.yml` 配了 Jackson `SNAKE_CASE`，该字段序列化为 `refresh_token`。

6. `dto/RefreshRequest.java`（新建）：字段 `refreshToken` + getter/setter。Jackson SNAKE_CASE 反序列化会把前端传来的 JSON 键 `refresh_token` 绑定到 `refreshToken`，与现有 `LoginRequest` 风格一致。

7. `service/AuthService.java`：
   - 注入 `RefreshTokenService`。
   - `login` / `register`：签发 access token 后追加 `String refreshToken = refreshTokenService.create(user.getId())`，返回 `new AuthResponse(token, refreshToken, username, userId)`。
   - 新增 `AuthResponse refresh(String refreshToken)`：
     - `RefreshToken row = refreshTokenService.findByRawToken(refreshToken)`；`row == null` 或 `revoked` → throw「刷新令牌无效」。
     - `row.getExpiresAt().isBefore(LocalDateTime.now())` → throw「登录已过期」。
     - `userMapper.findById(row.getUserId())` 为空 → throw「用户不存在」。
     - `refreshTokenMapper.revokeById(row.getId())`（旧 refresh token 旋转作废）→ `refreshTokenService.create(userId)` 签发新 refresh token（新 7 天窗口，实现滑动）→ `jwtUtil.generateToken(...)` 签发新 access token → 返回新 pair。
   - 新增 `void revokeRefreshToken(String refreshToken)`：`refreshTokenService.revoke(refreshToken)`。
   - `changePassword`：末尾加 `refreshTokenService.revokeAllForUser(userId)`（安全：改密后全端下线）。

8. `controller/AuthController.java`：
   - 新增 `@PostMapping("/refresh")`：`@RequestBody RefreshRequest` → `authService.refresh(...)`，成功返回 200 `ApiResponse.success(pair)`；catch 后返回 **401** `ApiResponse.error(401, e.getMessage())`（401 是给前端「刷新失败→登出」的信号，区别于 login/register 的 400）。
   - 改 `logout`：`@RequestBody(required = false) RefreshRequest`，非空且有 `refreshToken` 时 `authService.revokeRefreshToken(...)`，再返回 200。保持向后兼容（不传 body 也返回 200）。

**验证：** `cd backend && mvn -q -DskipTests compile` 通过（无编译错误）。依赖任务 01 的 DB 表已建好，方可启动后端做运行时验证。

**完成：** 登录/注册返回 `{ token, refresh_token, username, user_id }`；`POST /api/auth/refresh` 用旧 refresh token 换新 pair 并轮换作废旧 token；`/logout` 吊销对应 refresh token；改密吊销该用户全部 refresh token。

## 任务 03：前端 —— axios 拦截器滑动刷新 + store/api/types

**文件：**
- `src/axios/client.ts`
- `src/stores/auth.ts`
- `src/api/auth.ts`
- `src/api/type/auth.ts`

**动作：**

1. `src/axios/client.ts`（核心改动）：
   - 新增常量 `const REFRESH_TOKEN_KEY = 'auth_refresh_token'`。
   - 新增模块级 `let refreshPromise: Promise<void> | null = null`，实现**单飞**（并发 401 共享同一次刷新）：
     ```ts
     async function refreshAccessToken(): Promise<void> {
       if (!refreshPromise) {
         refreshPromise = doRefresh().finally(() => { refreshPromise = null })
       }
       return refreshPromise
     }

     async function doRefresh(): Promise<void> {
       const refreshToken = localStorage.getItem(REFRESH_TOKEN_KEY)
       if (!refreshToken) throw new Error('no refresh token')
       const res = (await api.post('/api/auth/refresh', { refresh_token: refreshToken })) as ApiResponse<any>
       if (res.code === 200 && res.data?.refresh_token) {
         localStorage.setItem(TOKEN_KEY, res.data.token)
         localStorage.setItem(REFRESH_TOKEN_KEY, res.data.refresh_token)
         return
       }
       throw new Error('refresh failed')
     }

     function clearAuthAndRedirect() {
       localStorage.removeItem(TOKEN_KEY)
       localStorage.removeItem(REFRESH_TOKEN_KEY)
       localStorage.removeItem(USERNAME_KEY)
       localStorage.removeItem(USERID_KEY)
       window.location.href = '/login'
     }
     ```
   - 响应拦截器重写为（保持成功分支返回 `response.data` 不变）：
     - 非 401/403：照旧 `ElMessage.error` 后 reject（业务错误路径不变）。
     - 401/403 且 `url` 命中 `/api/auth/login`、`/api/auth/register`、`/api/auth/refresh`、`/api/auth/logout`：**不触发刷新**（防死循环），提示后 reject；refresh 自身失败时提示「登录已过期，请重新登录」。
     - 401/403 受保护接口：若 `(error.config as any)._retried` 未置位 → 置位 → `await refreshAccessToken()` → `return api(error.config)` 重试一次（请求拦截器会用 localStorage 里的新 access token 自动重附 Authorization）；刷新失败 → `clearAuthAndRedirect()` 后 reject。
     - 已重试过仍失败：`clearAuthAndRedirect()` 后 reject。
   - `TOKEN_KEY/USERNAME_KEY/USERID_KEY` 保持原值；**不要改成功分支返回结构**。

2. `src/api/type/auth.ts`：
   - `AuthResponse` 增加 `refreshToken: string`（实际 JSON 键是 `refresh_token`，见下方 store 读取说明）。
   - 新增 `export interface RefreshRequest { refresh_token: string }`。

3. `src/api/auth.ts`：
   - 新增 `refresh = (data: RefreshRequest)` → `request<AuthResponse>({ method: 'POST', url: '/api/auth/refresh', data })`。
   - `logout` 改为可传 body：`logout = (data?: RefreshRequest)` → `request<void>({ method: 'POST', url: '/api/auth/logout', data })`。

4. `src/stores/auth.ts`：
   - 新增 `const STORAGE_REFRESH_KEY = 'auth_refresh_token'`（与 client.ts 同值）。
   - 新增 `readRefreshToken(data)` 兼容读取：`String(data?.refresh_token ?? data?.refreshToken ?? '')`（对齐现有 `readUserId` 的双命名兼容写法）。
   - `login` / `register`：额外 `localStorage.setItem(STORAGE_REFRESH_KEY, readRefreshToken(response.data))`。
   - `logout()`：先读 `const refreshToken = localStorage.getItem(STORAGE_REFRESH_KEY)`，`authApi.logout({ refresh_token: refreshToken }).catch(() => {})`，再连同 `STORAGE_REFRESH_KEY` 一起清除本地凭据。
   - `validateToken()`：保持现有逻辑不变——access token 过期时 `authApi.current()` 会 401，由 client.ts 拦截器自动刷新并重试，校验结果正确；仅当刷新也失败时才会走现有 catch 清除状态并返回 false（最终到登录页）。无需额外改动。
   - 说明：`main.ts` 无需改动，启动校验经拦截器自动获得刷新兜底。

**验证：** `npm run build` 通过（`vue-tsc --noEmit` + `vite build`）。

**完成：** 受保护接口 401 时自动单飞刷新并重试一次，用户无感；刷新失败才跳登录页；登录/注册/刷新/登出自身接口 401 不触发刷新死循环；logout 携带 refresh token 通知后端吊销；`auth_refresh_token` 与 access token 一起持久化。

**手动验收（`npm run tauri dev`，登录一次后）：**
1. **使用中不被踢**：登录后把 `auth_token` 改成过期/伪造值（保留 `auth_refresh_token` 真实值），继续操作（打开列表、进日历）→ 请求自动刷新成功、界面正常，**不跳登录页**。
2. **真正过期才登出**：把 `auth_refresh_token` 也改成伪造值后操作 → 跳到登录页（可接受）。
3. **登录/刷新/登出接口不循环**：伪造 access token + 伪造 refresh token，启动 → 进登录页（无死循环报错）。
4. **退出登录吊销**：正常登录 → 点退出 → 用刚才的 refresh_token 调 `/api/auth/refresh` → 返回 401（已被吊销）；重新登录后本地有新的 `auth_refresh_token`。
5. **改密吊销**：改密后旧 refresh_token 调 `/api/auth/refresh` → 401。
6. **自动登录仍正常**：正常登录后重启程序 → 直接进主界面（access token 有效直接过；已过期则走自动刷新再过）。
7. **旧会话兼容**：改部署前已登录、仅存 `auth_token` 的会话，其 24h access token 过期后因无 refresh token 会退回登录页一次（新登录后正常）——记录为已知可接受现象。
